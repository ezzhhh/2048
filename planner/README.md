# Планировщик задач (агент)

ИИ-агент ведёт общий планер: формулирует задачи, ставит приоритет, дробит на этапы и пишет решения в память — чтобы следующего агента можно было улучшить.

**Боевой контур — ваш сервер, не git.** Один адрес на ПК, ноут и телефон, вход только по паролю. Как поставить: `planner/server/DEPLOY.md`.

## Что это

Не отдельный сервер и не Telegram-бот. Рабочий контур:

1. Вы кидаете короткий тезис в чат (`+ …`, `готово …`, `фокус: проект`).
2. Агент прогоняет тезис через правила в `AGENT.md`.
3. Результат попадает на доску `ПЛАНЕР.md` (локальный файл, не коммитится).
4. Каждое решение и закрытие задачи пишется в `memory/` — это и есть «память» для модернизации.

ИИ здесь — сам агент Cursor, по фиксированным правилам. Скоринг, lint и «следующий шаг» — ещё и в `python -m planner.cli` (без отдельного LLM-API).

## Файлы

| Файл | Назначение |
|---|---|
| `AGENT.md` | Как думать: формулировка, приоритет, декомпозиция, память |
| `СТАРТ_ЧАТА.md` | Вставить в новый Agent Chat |
| `ПЛАНЕР.example.md` | Образец доски без рабочих данных |
| `ПЛАНЕР.md` | Живая доска (gitignore, создать из example) |
| `memory/DECISIONS.md` | Решения по устройству планировщика |
| `memory/LESSONS.md` | Что менять в агенте |
| `memory/SESSIONS.md` | Журнал сессий |
| `memory/TASK_LOG.md` | Лог закрытых задач и развилок |
| `memory/private/` | Черновики с внутренними id (gitignore) |

## Быстрый старт

```bash
cp planner/ПЛАНЕР.example.md planner/ПЛАНЕР.md
```

Откройте папку `planner/` (или `C:\Users\user\Plans` с копией этих файлов) как workspace. Вставьте текст из `СТАРТ_ЧАТА.md` в новый чат.

Команды: `+ задача` · `срок …` · `готово …` · `список` · `фокус: проект` · `разбей …`

```bash
python3 -m planner.cli next --board planner/ПЛАНЕР.md
python3 -m planner.cli list --board planner/ПЛАНЕР.md --focus restoris
python3 -m unittest planner.tests.test_engine
```

Образец ИИ-прохода без рабочих id: `planner/fixtures/backlog.example.md`.

## Память и улучшение агента

После `готово` агент обязан:

1. Записать строку в `memory/TASK_LOG.md` (что закрыли, какое решение, исход).
2. Если всплыло правило или ошибка — пункт в `memory/LESSONS.md`.
3. Если урок повторился дважды — перенести формулировку в `AGENT.md`.

Так история решений не пропадает с чатом и следующий прогон агента становится точнее.

## Секреты

Живая доска и `memory/private/` не попадают в git. В публичный репозиторий не класть CRM id, токены, телефоны.

Уведомления на ПК/телефон (Slack / Telegram / Cursor) — только по явной команде.
