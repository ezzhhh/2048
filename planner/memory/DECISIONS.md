# Решения по устройству планировщика

Пишем сюда развилки «как устроен агент», не рабочие задачи проектов.

## 2026-09-04 · D001 · Контур = Cursor-агент + файлы, не отдельный сервер

- Решение: ИИ-анализ (приоритет, формулировка, этапы) делает агент по `AGENT.md`. Отдельный LLM-API и веб-приложение не нужны на этом шаге.
- Почему: inbox уже этот чат; правила можно менять в git; меньше движущихся частей.
- Иначе если: понадобится разбор тезисов без открытого чата — тогда скрипт/бот поверх тех же файлов.

## 2026-09-04 · D002 · Память = markdown в memory/, не «надежда на чат»

- Решение: каждое `готово` и каждая развилка → `TASK_LOG`. Урок → `LESSONS`. В `AGENT.md` только повтор (2 раза) или явная команда «запомни как правило».
- Почему: чаты сгорают; модернизация агента = перенос устойчивых уроков в правила.

## 2026-09-04 · D003 · Живая доска не в публичном git

- Решение: `planner/ПЛАНЕР.md` и `memory/private/` в `.gitignore`. В репозитории — example и правила.
- Почему: на доске внутренние id воронок и статусов.

## 2026-09-04 · D004 · Уведомления ПК/телефон — отдельная команда

- Решение: Slack / Telegram / только Cursor. Не подключать, пока канал не назван. Раньше Telegram был на стопе.
- Иначе: агентный таймер будит чат, не центр уведомлений ОС.

## 2026-09-04 · D007 · Источник правды — свой сервер

- Решение: веб-приложение на вашем сервере, SQLite, один пользователь, без git.
- Почему: доступ только у владельца; ПК / ноут / телефон смотрят одну доску.
- Git остаётся только способом перенести код один раз, в рантайме не участвует.

## 2026-09-04 · D006 · Скоринг и lint — код, формулировка — агент

- Решение: `planner/engine.py` считает P0–P3, ловит пустые глаголы и развилки; человеческую формулировку по-прежнему пишет агент.
- Почему: правила из AGENT.md не должны расходиться от сессии к сессии; тесты фиксируют шкалу.
- Алиасы проектов: `restoris` = `ресторис`, и т.п.

## 2026-09-04 · D005 · Команда «стоп» закрывает Goal

- Решение: после явного стопа — UpdateGoal complete, не продолжать хвосты и не слать повторные «мы на паузе».
- Почему: активный Goal будит агента системными продолжениями.
